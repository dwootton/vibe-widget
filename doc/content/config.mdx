Configure model settings and API keys.

## Set defaults

```python
import vibe_widget as vw

vw.config(model="openai/gpt-5.1-codex")
vw.config(mode="premium", model="openrouter")
vw.config(execution="approve")
```

## API key setup

Put one key in a `.env` file next to your notebook and you are done:

```bash
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
OPENROUTER_API_KEY=sk-or-...
```

The file is searched for in the working directory and its parents, stopping at the repository root
or your home directory. A variable already present in the environment is never overwritten, so an
exported value always wins over the file. No extra dependency is needed; do not call
`dotenv.load_dotenv()` yourself.

Exporting the variable works identically:

```bash
export ANTHROPIC_API_KEY='your-key'
```

```powershell
$env:ANTHROPIC_API_KEY="your-key"
```

We recommend avoiding hardcoded keys in notebooks to prevent accidental leaks.

## Provider inference

When you do not set `base_url`, the key you supplied decides the endpoint and the default model.

| Variable | Endpoint | Default model |
| --- | --- | --- |
| `VIBE_API_KEY` | `VIBE_BASE_URL`, or OpenRouter | depends on the endpoint |
| `ANTHROPIC_API_KEY` | `https://api.anthropic.com/v1/` | `claude-opus-5` |
| `OPENAI_API_KEY` | `https://api.openai.com/v1` | `gpt-5.5` |
| `OPENROUTER_API_KEY` | `https://openrouter.ai/api/v1` | `google/gemini-3-flash-preview` |

They are checked in that order, so `VIBE_API_KEY` overrides everything and `OPENROUTER_API_KEY` is
the last resort. An explicit `vw.config(api_key=...)` beats all of them. If a key looks like it was
issued by a different vendor, for example an `sk-ant-` value stored in `OPENAI_API_KEY`, the
variable name decides and a warning is printed once.

`vw.config()` reports what was inferred, without ever showing the key:

```python
vw.config()
# Config(provider='openai', host='api.openai.com', model='gpt-5.5',
#        key_source='OPENAI_API_KEY (/work/analysis/.env)', environment='quarto', ...)
```

`provider` is derived from the endpoint and reads `anthropic`, `openai`, `openrouter` or `custom`.
`environment` lists the notebook hosts detected for this kernel, such as `vscode-like` for VS Code
and Positron, `quarto`, `colab` or `pyodide`.

Changing the model alone keeps the provider your key selected:

```python
vw.config(model="claude-sonnet-5")   # still Anthropic
```

Model IDs carrying an OpenRouter-style `vendor/` prefix are rejected on a direct provider, because
`anthropic/claude-opus-4.5` is not a name Anthropic's own API knows. Use the plain name, or set
`base_url` to OpenRouter.

## Endpoint

Set `base_url` to reach any other OpenAI-compatible server, including a local one.

```python
vw.config(base_url="http://localhost:11434/v1", model="qwen2.5-coder")   # Ollama
vw.config(base_url="http://localhost:8000/v1", model="Qwen/Qwen2.5-Coder-32B")  # vLLM
```

A loopback endpoint (`localhost`, `127.0.0.1`, `::1`) needs no API key at all, since local servers
ignore it. Set `VIBE_API_KEY` anyway if yours sits behind an auth proxy.

For an endpoint with no dedicated variable, such as vLLM behind an auth proxy or Azure OpenAI, set
both `VIBE_API_KEY` and `VIBE_BASE_URL`:

```bash
VIBE_API_KEY=your-key
VIBE_BASE_URL=https://my-resource.openai.azure.com/openai/v1
```

Requests adapt to what the endpoint accepts. Newer OpenAI models want `max_completion_tokens`
instead of `max_tokens`, and some models reject `temperature` outright; the rejected parameter is
renamed or dropped and remembered, so only the first call to a given endpoint pays for the
correction.

`timeout` is the HTTP timeout in seconds for a single model call, 120 by default. Raise it for slow
local models.

```python
vw.config(timeout=300.0)
```

## Common configuration options

```python
vw.config(
    execution="auto",   # "auto" or "approve"
    retry=2,            # Runtime repair attempts
    agent_preset="project",
    agent_run={"permission_tier": 1, "allowed_roots": ["."]},
    bypass_row_guard=False,
    base_url=None,      # None means infer from whichever API key is set
    timeout=120.0,      # HTTP timeout, seconds
    data_privacy="sample",  # "sample" or "schema"
    sample_rows=3,      # rows sent per input in "sample" mode
)
```

## Safety and permissions

Generated code runs in the notebook page with the same privileges as the page itself. It can reach
the DOM, cookies and `localStorage` for the notebook origin, and any network endpoint the browser
is allowed to call. There is no browser-level sandbox around it. Treat a generated widget the way
you would treat a script someone sent you.

### Execution mode

Control whether code runs immediately or requires manual approval first.

```python
vw.config(execution="approve")   # review code before it runs
vw.config(execution="auto")      # run immediately (default)
```

In `"approve"` mode the generated code is not executed until you approve it. Approval is decided in
Python, not in the browser, so a widget cannot approve itself. The widget tracks a SHA-256 hash of
the approved code; if the code changes after an edit or a retry, approval resets and you approve
again.

### Agent presets

Agent presets control which tools the LLM agent can call. There are three levels:

| Preset | Permission tier | File access | Network | Use case |
| --- | --- | --- | --- | --- |
| `"safe"` | 0 (read-only) | Sandbox only | No | Sensitive data, minimal risk |
| `"project"` | 1 (read-write) | Working dir + sandbox | No | General use (default) |
| `"connected"` | 2 (full) | Working dir + sandbox | HTTPS only | Fetching remote data |

```python
# Lock down to read-only tools
vw.config(agent_preset="safe")

# Default: read-write in your project directory
vw.config(agent_preset="project")

# Allow the agent to fetch URLs (HTTPS only)
vw.config(agent_preset="connected")
```

**Tier 0 tools** – `data.profile`, `fs.list`, `fs.read`, `fs.exists`, `fs.glob`, `state.get`, `state.put`, `pls.describe`

**Tier 1 adds** – `data.load`, `fs.write`, `fs.mkdir`, `fs.read_base64`

**Tier 2 adds** – `net.fetch` (HTTPS only, host and MIME allowlisted, requires `allow_net_fetch`)

### Row guard

By default, datasets over 100,000 rows are blocked to prevent memory exhaustion.

```python
# Keep the guard (default)
vw.config(bypass_row_guard=False)

# Disable if you need large datasets
vw.config(bypass_row_guard=True)
```

### Model modes

Models are grouped into two modes:

| Mode | Models | Trade-off |
| --- | --- | --- |
| `"standard"` | Gemini 3 Flash, Claude Haiku 4.5, GPT-5.1 Codex Mini | Fast, lower cost |
| `"premium"` | Gemini 3 Pro, Claude Opus 4.5, GPT-5.1 Codex | Higher quality, higher cost |

```python
vw.config(mode="standard")   # default
vw.config(mode="premium")
```

### Recommended secure configuration

For sensitive data or shared environments, lock things down:

```python
vw.config(
    execution="approve",          # require manual approval
    agent_preset="safe",          # read-only tools, sandboxed
    bypass_row_guard=False,       # enforce row limit
    retry=0,                      # no automatic code repairs
)
```

## Privacy and telemetry

Vibe Widget sends the following to the model provider:

- your prompt and theme prompt
- a schema summary of each input: shape, column names, dtypes, null counts, cardinality, and numeric min/max/mean
- the first `sample_rows` rows of each input, 3 by default, when `data_privacy` is `"sample"`
- outputs/inputs descriptors
- full widget code for edits, audits, and runtime fixes
- runtime error messages (when auto-fixing)

### Controlling what leaves the notebook

`data_privacy` chooses between the two summary modes.

```python
vw.config(data_privacy="schema")   # schema only, no cell values
vw.config(data_privacy="sample")   # schema plus head rows (default)
vw.config(sample_rows=1)           # fewer rows in "sample" mode
```

In `"schema"` mode the summary carries no cell values: no head rows, no category examples, no
sampled values. Only the shape and the per-column description go out. Non-tabular inputs are
summarized by type and length, and their truncated `repr` is included in `"sample"` mode only.

`data_privacy` governs the data summary built from the values you pass to `vw.create`. It does not
restrict the agent's `data.profile` tool, which reads sample values from any file it is allowed to
open. Combine `data_privacy="schema"` with `agent_preset="safe"` to keep the agent out of your
project directory as well.

No API keys are written to disk. Generated widgets and audit reports are stored locally in `.vibewidget/`.
